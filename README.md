# 萬卷浮城：梁山閱征記

國中七至九年級個人化閱讀系統。學生一次專心完成一篇，系統按人保存閱讀與結構化答題結果；達到三題中答對兩題的門檻後，可接著挑戰下一篇，也可選擇今天結束、明天再來。介面以手機與平板優先，採 Q 版人物、國畫潑墨與水彩流動邊緣的原創水滸靈感世界。

## 專案狀態

正式環境已部署，三站共用同一個 Cloudflare Worker API 與 Production D1：

- Cloudflare Pages：https://reading-expedition-2u1.pages.dev/
- Vercel：https://reading-expedition.vercel.app/
- Netlify：https://reading-expedition.netlify.app/
- GitHub：https://github.com/hk6429/reading-expedition

## 核心功能

- 啟航（300–600 字）、行舟（700–1,000 字）、登樓（1,300–1,700 字）是三個獨立文章庫，學生可自由切換。
- 第一次可用一篇完整短文與三題完成五分鐘測讀；結果只推薦起點，不鎖級。
- 引導模式提供段落路標與領航提示；獨立模式保留點詞解釋，讓孩子自己整理文章。
- 正文生難詞可直接點擊，查看文中義與短例句。
- 每完成五篇只提示「可以試試下一級」，不自動升降級。
- 每篇固定三題：找重點、想意思、找證據；手機與平板一次只顯示一題。
- 每篇完成問答後提供專屬「閱讀專家拆解」，以文章結構、三步策略、本文示範與自我檢核，把答題經驗轉成可遷移的閱讀方法。
- 答錯只說明所選錯項與原文的落差，不洩漏正解；學生可回看 8–30 字精準文證並修正一次。
- 30 個活躍日章回、四階段浮城成長與每週文證回顧。
- 30 個活躍日主線統一為 20 次建城與 10 次故事／回顧解鎖；每個活躍日第一篇達標閱讀推進主線，額外閱讀仍會收藏。
- 常駐「我的浮城」提供城市全景、建築文證收藏、三項閱讀能力裝備、下一回預告與每週彈性目標。
- 同一能力須在至少兩篇文章、第一次作答成功展現三次，才解鎖對應裝備；修正成功另記為修正力。
- 本機閱征事件簿保存文章名稱與實際原文文證，同日額外閱讀也看得見；並支援 JSON 下載與安全復原。
- 每次進入先提醒下載個人備份；多人共用裝置時，以家庭護照的孩子代號切換彼此獨立的閱讀、答題與浮城紀錄。
- 選配「家庭護照」可跨手機與平板同步；每位孩子有獨立浮城、閱讀診斷與裝備，家長可下載單一孩子或全家庭 CSV。
- 本機優先、離線閱讀、匿名班級共同地標。
- 班級共同地標顯示匿名共同任務與距下一階的整體進度，不顯示個人排名。
- 教師安全登入、雙版本校閱、退回、發布、下架與稽核紀錄。
- 教師可建立匿名班級、立即複製 8 碼班級碼、查看參與概況與停用班級；停用後既有學生權杖同步失效。
- 師生使用說明分成學生四步與教師四步，手機上也能直接查看。
- 右下角共用元件提供「返回自學星圖」入口，以及目前在線、今日到訪與累積到訪統計；手機／平板預設收合，避免遮住內容。
- 學生可在使用說明退出匿名統計；退出後不送學習事件，也不載入到訪計數器。
- 教師可在本機用已登入的 Codex CLI 隨時新增主題；來源、文章與題組通過自動檢核後，仍先進教師校閱。
- 正式手動內容庫採長文規格：白話文每篇 1,300–1,700 個漢字；文言文每篇 500–900 個漢字並附 8–15 則正文內注釋。既有短篇種子僅供系統安全示範。
- 命題參考會考與學測的閱讀能力層次，但明文禁止複製或改寫歷屆考題。
- 來源、授權、事實、原創度、難度、題目、安全與品質 92 分發布門檻。

## 資料邊界

- 未建立家庭護照時，個人閱讀位置、城市、收藏與偏好只保存在這部裝置。
- 家庭護照是選配功能；建立後只使用孩子代號，伺服器同步分級偏好、結構化診斷、城市與裝備狀態。
- 系統不收姓名、學號、Email、學校或班級真名，也不保存自由反思或作答文字。
- 家庭護照碼就是跨裝置鑰匙；伺服器只保存不可逆雜湊，明碼只在建立當下顯示一次。
- 未選家庭護照時，伺服器只保存內容、審核稽核、固定欄位匿名成效事件與達五人門檻的班級彙總。
- 班級碼在伺服器只保存雜湊；明碼只在教師建立當下與該教師分頁暫存中顯示。
- 不使用公開排行榜、抽卡、斷簽歸零或侵入式監控。

## 本機開發

需求：

- Node.js 24 LTS
- npm

安裝、建置與測試：

```sh
npm ci
npm run build
npm test
npm run test:e2e
```

啟動包含 Pages Functions 的本機站：

```sh
npm run dev:web
```

預設位置為 `http://127.0.0.1:8788`。

## 系統架構

- 三個靜態前端：Cloudflare Pages、Vercel、Netlify。
- 單一中央 API：Cloudflare Worker。
- 中央資料庫：Cloudflare D1，Preview 與 Production 完全分離。
- 正式環境不設內容生成排程，也不綁定雲端 AI；內容由本機 Codex CLI 人工選題與產生。
- 後端部署固定使用 `npm run deploy:worker`；`wrangler.worker.toml` 與 Pages 本機測試設定分離。
- 前端一律使用同源 `/api`；平台代理由 `READING_API_ORIGIN` 設定。

## 手動新增閱讀內容

Codex CLI 會沿用本機已登入的 ChatGPT 身分，不必把 OAuth 憑證或 API Key 寫進專案。每次自行選一個主題：

```sh
npm run content:new -- --slug moon-phases "月相為什麼會改變"
```

草稿會寫入 `content/manual/drafts/`，且不覆寫同名檔。可隨時檢查目前累積內容：

```sh
npm run content:validate
```

完成 30 組主題後，再執行完整數量與三類配額檢核，產生 D1 匯入檔：

```sh
npm run content:ready
npm run content:sql
```

既有 60 篇正式長文會匯入登樓文章庫；較短的啟航與行舟文章另行策展，避免只把同一篇文章裁短充數。所有匯入內容仍先進待審稿，必須由教師核准才會上線。

## 測試

- Node 內建測試：領域、儲存、API、資料庫、生成管線、資安、效能與靜態契約。
- Playwright：手機、平板、桌機、離線、鍵盤、200% 字級、reduced motion 與完整閱讀流程。
- CI 固定 Node.js 24，Pull Request 與 main push 均執行完整測試。
